# 点餐诉求修复与验证

本次已修复诊断报告中的指定餐品漏选、否定反向加分、上诉无法纠正与判词虚构理由。以下记录修复范围与本地验证结果；提交和推送不代表已完成线上部署验证。

## 修复内容

1. `lib/court/preferences.ts` 从当前菜单建立名称匹配，支持“板烧”简称、指定餐品、排除项、“只要”、多项同时要求及“或”的选择关系。先解析条件，再优化价格与份量。明确但无法匹配的餐品返回菜单缺口，价格未知、超预算和条件冲突分别说明。
2. `lib/court/recommend.ts` 的主方案和全部备选共用这些条件。“不要薯条”不会再触发薯条加分；有指定餐品时不会悄悄以其他食物替代。仅要饮料时不会为满足默认饥饿目标额外添加食物。
3. 首次推荐和上诉共用同一解析与选择逻辑，支持重申要求、“换成”和“只要”的后续调整；无法满足上诉时展示具体原因并保留原方案。
4. 餐品类别与份量估计移至 `lib/court/meals.ts` 共用，四件套正确识别为组成未确认的套餐，不当作单个汉堡或用于证明包含指定饮料。
5. `lib/ai/judge.ts` 接收明确的诉求满足情况、未检查库存及未创建订单事实。具体的匹配理由由规则保留，AI 不再覆盖。对缺货、替换、已下单、强迫接受等不受事实支持的文案进行校验，拒绝后保留规则判词；诉求未满足时直接保留具体缺口说明。
